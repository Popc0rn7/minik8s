Minik8s: A More Modular, More Unified Fleet

一个轻量容器编排系统，参考 Kubernetes 设计，重新设计组件边界和交互， 核心编排闭环。

Minik8s 简介

核心闭环

Kubernetes-like workflow用户只面对 apply、get、describe、delete 的资源工作流。

Bridge control plane统一 API、状态存储、调度和 controllers，持续收敛期望状态。

Sailer worker plane在节点上创建 Docker 容器，执行 CNI，并同步本地 data plane。

Kubectl + Harbor APICLI 通过 Harbor 读写资源，展示对象状态、日志和 Metrics。

系统架构

Minik8s 把控制面和节点面拆成一条清晰的对象流。用户只操作 Kubectl，服务提供者 只考虑在机器上启动Node，达成用户无感，健壮性强，拓展性强。

Bridge 作为控制面核心，由4大组件构成，协同工作。 Sailer 作为节点面核心，负责实际任务和容器的运行。

  • Harbor 暴露 Kubernetes-like API，处理 YAML 对象 CRUD、Node Join Token、Heartbeat、Pod Status 和 Metrics 上报。
  • Logbook 作为统一状态存储，默认写本地 JSON；设置 Etcd endpoint 后把 Pod、Service、ReplicaSet、Node 等对象持久化到 Etcd。
  • Navigator 监听 Pending Pod，为其选择 Ready Node 并写入 spec.nodeName，Unknown Node 会被调度避开。
  • Captain 运行 controller loop，收敛 Service endpoints、ReplicaSet replicas、HPA replicas 和 Node lifecycle。
  • Sailer 运行在 Worker 上，拉取 Assigned Pods，创建 Sandbox/Container，调用 CNI，回写状态，并同步 Kube-proxy 规则。

Self-built CNI: Mooring

Mooring 在兼容第三方 CNI 调用方式的基础上，实现 Minik8s 自研数据面： 节点内用 bridge/veth 连接 Pod，节点间由 Sailer 同步 VXLAN/FDB/route。

  • 兼容 CNI ADD/DEL/CHECK。
  • 创建 bridge/veth、分配 Pod IP、写入默认路由。
  • Sailer: 跨节点 VXLAN、FDB、route 同步。
  • Kube-proxy: ClusterIP / NodePort iptables 转发。

Reconciliation & Heartbeat

用户提交的是期望状态，控制面周期性比较 desired/current， 并把差异收敛到实际集群。

  • Service controller 维护 selector endpoints，Pod 增删、NodeLost 后自动刷新。
  • ReplicaSet controller 维持 desired replicas，owned Pod 丢失后补齐副本。
  • HPA controller 读取 Docker CPU/Memory Metrics，按简化策略调整 Replicas。
  • Heartbeat 超时后 Node 标为 Unknown，并触发 endpoints 与副本重新收敛。

Deps Pod & Addon Pod

Init 时自动生成 Deps Pod manifests; Bridge 启动时运行内部 Private Sailer Private Sailer 负责启动 Deps Pod 如storage-etcd, 并按 --addons 的需求可选地拉起 DNS、Metrics、Serverless 依赖Pod， 协同Captain和Harbor来进行能力拓展。

Serverless

基于 Minik8s 控制面实现教学版 Serverless 闭环。Function、EventTrigger 和 Workflow 作为一等资源接入 YAML loaders、Harbor APIs、file/Etcd stores； 调用统一进入 NATS request/reply，再由 invocation worker 和 Activator 完成冷启动、扩缩容和 Pod /invoke 转发。

Resource model Function 支持内联 Python 与自定义容器镜像；controller 映射为 fn-* ReplicaSet + Service，并维护 revision/update/delete。
NATS Serverless addon 启动 NATS；CLI invoke、EventTrigger 和 Workflow step 都通过 request/reply 进入统一调用入口。
Invocation Worker 订阅 minik8s.serverless.invoke queue group，解析 namespace/function/data，并把请求交给 Activator。
Activator 冷启动时把 ReplicaSet 从 0 拉到 1，等待 Running、PodIP 和 TCP 可达后转发 HTTP /invoke。
EventTrigger 订阅用户配置的 NATS subject，收到事件后复用同一条调用链触发 Function。
Workflow 支持同步函数链、前后 step 数据传递，以及基于 contains/regex 输出匹配的分支。

GPU Job 扩展

Minik8s 提供最小 Job + Slurm Submitter 后端。GPU Jobs 通过 accelerator=gpu 声明任务，提交 CUDA source 和 commands， 并回收 Slurm .out/.err 日志。

Job YAML
CUDA + command Harbor API
store Job Submitter Pod
SSH / SCP SJTU Slurm
sbatch Status / Logs
.out .err

Job YAML 随 Kubectl apply 上传 CUDA source 和 commands； Job Controller 创建 Submitter Pod/Service；Submitter 通过 SSH/SCP 执行 sbatch；完成后回收 Job ID、状态和 .out/.err， 写回 Minik8s Job status。Slurm 节点不纳入 Minik8s 集群。
